# 사람들은 Hermes 를 어디에 쓰나

세팅을 끝낸 뒤 "이제 무엇을 시키지?"에 답하려고 만든 문서입니다.
2026-11-23 에 공개된 글을 찾아 다섯 가지를 골랐습니다.

먼저 알아 둘 것:

- **이 레포에서 직접 해 본 사례가 아닙니다.** 다른 사람이 공개한 글을 옮긴 것입니다.
- 검색되는 글 상당수가 호스팅 업체나 강의 판매자의 홍보 글입니다. 수치는 걸러 읽으세요.
- 이 레포의 구성(디스코드, 메모리 1GB, 브라우저 기능 없음, 본인 한 명만 대화)으로 바로 되는 것은 거의 없습니다. 사례마다 더 필요한 것을 적었습니다.

Hermes 를 따로 설치해서 쓰는 이유는 [README 의 "ChatGPT 와 무엇이 다른가"](../README.md#chatgpt-와-무엇이-다른가)에 있습니다.
아래 사례는 전부 그 차이 세 가지에서 나옵니다. 꺼지지 않는다, 메신저에 붙어 있다, 한 번 한 일을 스킬로 남긴다.

## 한눈에 보기

| | 사례 | 쓰는 기능 | 이 레포 구성에서 더 필요한 것 |
|---|---|---|---|
| 1 | 영업 문의 처리 | 메신저 연동, 스킬 | 슬랙 연동, 메일·문서 도구 연결 |
| 2 | 정기 브리핑과 모니터링 | 예약 작업 | 예약 작업 확인, 웹 조회 도구 |
| 3 | 가격 감시와 리드 발굴 | 웹 수집, 예약 작업 | 웹 수집 도구. 메모리가 모자랄 수 있습니다 |
| 4 | 가족·소규모 팀 공용 비서 | 메신저 연동, 기억 | 대화 허용 인원 추가. 안전 문제가 따릅니다 |
| 5 | 오류 분석과 배포 전 점검 | 서버 명령 실행 | 점검할 코드가 서버에 있어야 합니다 |

## 1. 영업 문의 처리

국내 개발사 똑똑한개발자가 공개한 사례입니다.
슬랙에 붙인 Hermes 가 문의 접수, 첫 답장 메일, 견적서와 계약서 작성, 세금계산서 발행 요청까지 이어서 처리합니다.
공개된 사례 가운데 맡긴 업무의 시작과 끝이 가장 분명합니다.

- 더 필요한 것: 이 레포는 디스코드만 연결합니다. 슬랙 연동과 메일·문서 도구 연결은 따로 해야 합니다.
- 출처: [Hermes 영업 AI 에이전트 세팅 가이드](https://www.openads.co.kr/content/contentDetail?contsId=19619)

## 2. 정기 브리핑과 모니터링

가장 흔한 쓰임입니다. 매일 뉴스 확인, 주간 주제 조사, 관심 종목 데이터 갱신처럼 반복되는 일을 시간을 정해 맡깁니다.
결과는 메신저로 받습니다.

- 더 필요한 것: 예약 작업은 Hermes 에 들어 있는 기능이지만 이 레포에서는 아직 확인하지 않았습니다. 웹을 조회하는 도구 설정도 확인하지 않았습니다.
- 출처: [에르메스 에이전트로 나만의 에이전트 시스템 구축하기](https://brunch.co.kr/@pletalk/237)

## 3. 가격 감시와 리드 발굴

매물 사이트를 주기적으로 읽고, 시세보다 싼 것이 나오면 알려 주는 방식입니다.
한 테스트에서는 비슷한 차가 18만 파운드에 올라와 있는데 12만 5천 파운드에 나온 매물을 찾아냈습니다.
같은 글에 웹사이트가 없는 업체를 찾아 업체마다 제안 방향과 첫 문장을 붙여 주는 리드 발굴 예도 있습니다.

- 더 필요한 것: 웹 페이지를 읽어 오는 도구가 있어야 합니다. 이 레포는 브라우저 기능을 설치하지 않았고, 메모리 1GB 로는 무거울 수 있습니다.
- 출처: [5 Autonomous Tasks the Hermes Agent Handles Better Than OpenClaw](https://www.mindstudio.ai/blog/5-autonomous-tasks-hermes-agent-handles-better-than-openclaw-real-output-examples)

## 4. 가족·소규모 팀 공용 비서

Hermes 하나를 왓츠앱에 붙여 가족 세 명이 각자 용도로 같이 쓴 사례입니다.
ChatGPT 구독을 끊고 옮겼고, 총비용이 200달러 아래였다고 합니다.
출처 글이 원래 사례의 링크 없이 전하는 이야기입니다.

- 더 필요한 것: 이 레포는 본인 한 명만 대화하도록 세팅합니다. 봇에게 말을 걸 수 있는 사람은 서버를 조작할 수 있는 사람이기 때문입니다. 사람을 추가하기 전에 [README 의 "안전에 관해"](../README.md#안전에-관해)를 읽으세요.
- 출처: [Hermes Agent Use Cases](https://fast.io/resources/hermes-agent-use-cases/)

## 5. 오류 분석과 배포 전 점검

개발하는 사람에게 맞는 쓰임입니다. 오류 로그를 읽고 원인과 볼 파일을 정리하게 합니다.
출처 글이 권하는 방식은 조심스럽습니다. 분석은 맡기되 수정은 승인한 뒤 한 번에 한 파일만 시킵니다.
메신저에서 부를 때는 읽기와 요약만 허용하는 데서 시작합니다.

- 더 필요한 것: 점검할 코드와 로그가 Hermes 가 도는 서버에 있어야 합니다.
- 출처: [Hermes Agent 활용 예시 (위키독스)](https://wikidocs.net/374501)

## 사례를 따라 하기 전에

- **비용이 늘 수 있습니다.** 예약 작업은 내가 부르지 않아도 모델을 씁니다. 이 레포 구성에서는 ChatGPT 구독 한도를 씁니다.
- **권한을 넓히는 일입니다.** 메일, 고객 정보, 결제 문서에 닿게 할수록 잘못됐을 때의 피해도 커집니다. 읽기만 허용하는 데서 시작하세요.
- **웹에서 읽어 온 글이 지시처럼 작동할 수 있습니다.** 웹 수집을 맡길 때는 그 결과로 무엇을 실행할 수 있는지 먼저 정해 두세요.
- **ChatGPT 도 예약과 기억 기능을 넣고 있습니다.** 2번 같은 사례는 앱만으로 되는지 먼저 확인해 보세요.
